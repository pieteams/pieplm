# 生态概览

PiePLM 不打算成为一体化套件。它的定位是在工程文件、企业系统和 AI Agent 之间，暴露一小套有文档的接口，供其他工具使用。

本页描述目标生态：PiePLM 周围的系统、集成方式，以及项目偏好的标准。

## PiePLM 的位置

```text
CAD / Office 文件        ERP / 采购            质量系统
        │                       │                       │
        └───────────┬───────────┴───────────┬───────────┘
                    ▼                       ▼
              ┌─────────────────────────────────┐
              │            PiePLM               │
              │  产品、版本、BOM、变更、需求      │
              └───────────────┬─────────────────┘
                              │ API / MCP
                ┌─────────────┴─────────────┐
                ▼                           ▼
          BI / 报表                     AI Agent
```

PiePLM 拥有产品定义及其变更历史。它不拥有财务、采购、制造执行或文件编辑工具。那些系统保留自己的职责，通过接口交换数据。

## 集成方式

### REST API

主要集成路径。下游系统通过 `/api/v1` 读取产品、版本、BOM 和变更。写入仅限模块显式支持的操作，并经过认证和审计。

### Webhook 与事件

状态变化会发布事件：版本发布、变更批准、文档附加、不符合项开启。消费者可以订阅而不是轮询。初始设计倾向于至少一次投递加幂等消费，并提供遗漏事件的重放窗口。

### 文件交换

制造供应链仍然在交换文件。目标支持：

- **STEP（ISO 10303）**：在有查看器或转换器的情况下交换 CAD 几何
- **PDF**：受控文档，如图纸和规范
- **CSV / XLSX**：产品和 BOM 数据的导入导出
- **ZIP 包**：导出某版本及其文档和 BOM

文件交换是边界，不是数据模型。导入的文件成为带校验和的附件；导入的表格数据在创建记录前先校验。

### MCP

AI Agent 通过 Model Context Protocol 访问同一领域模型。默认只读；写工具需要显式范围，且永远不能批准。见 [MCP 集成](/zh-CN/guide/mcp-integration)。

## 标准

PiePLM 偏好开放、可检查的格式：

| 关注点 | 标准 |
| --- | --- |
| API 描述 | OpenAPI 3.1 |
| 身份 | 人类登录使用 OIDC；机器使用限定范围的 Bearer Token |
| 错误 | RFC 9457 问题详情 |
| 时间 | RFC 3339，UTC |
| 文档 | 需要归档时使用 PDF/A；保留原始格式 |
| 几何交换 | 适用时使用 STEP |
| Agent 工具 | Model Context Protocol |

当某个标准对小团队不现实时，项目会记录偏离之处，而不是悄悄发明私有格式。

## 关联的 PieTeams 项目

### PieMDM

PieMDM 治理跨系统的客户、供应商、物料、组织和参考字典等主数据。PiePLM 与 PieMDM 在产品与供应商身份上有重叠。

目标边界：

- **PieMDM** 是多系统共享主数据的权威来源。
- **PiePLM** 是产品定义、版本内容和变更历史的权威来源。
- 通过映射表把 PiePLM 产品关联到 PieMDM 产品记录；双方都不复制对方的完整记录。

### PieKBS

PieKBS 将文档蒸馏为 Agent 可检索的 Markdown Wiki。PiePLM 存结构化记录，PieKBS 存叙述性知识和原始文档。

组合流程可能如下：

1. 规范文件附加到 PiePLM 的某个版本。
2. PieKBS 将规范蒸馏为来源笔记，并更新相关概念页。
3. Agent 先在 PieKBS 搜索设计理由，再读取 PiePLM 的权威版本和 BOM。

这种分离是有意的。结构化记录和经过整理的知识有不同生命周期、权限和失败模式。

## 不计划的内容

为了保持范围诚实，以下内容不属于初始生态：

- 付费插件市场
- 私有文件格式
- 由项目运营的托管 SaaS
- 认证或合规保证
- 替代 ERP、MES 或 CRM

欢迎第三方基于 API 构建。项目只负责记录契约，不运营应用商店。
